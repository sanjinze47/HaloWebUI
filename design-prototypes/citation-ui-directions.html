协议兼容不能只看接口是否返回成功

不同网关可能暴露相同的模型名称和接口路径，但对请求字段、工具调用和流式终止事件的解释并不相同。OpenAI 的 Responses API 要求以明确的终止事件判断成功，而不能把自然断流当作完成。

图片编辑也存在类似差异：标准 OpenAI-compatible 服务通常接收 multipart 文件，grok2api 则使用 JSON data URL。仅凭 grok-imagine-image 模型名无法区分官方 xAI 与私有兼容网关。

  • 模型名用于判断能力候选，例如是否可能支持图片编辑。
  • 连接类型用于确定实际协议，避免错误请求或重复计费。
  • 正文引用只显示稳定编号，标题、域名、原文摘录和完整链接统一放在来源详情中。

对普通用户，连接配置可以默认自动推荐；对无法可靠识别的反向代理，则保留显式覆盖。这样既减少设置负担，也不会在真实生成请求中进行有副作用的盲目重试。
